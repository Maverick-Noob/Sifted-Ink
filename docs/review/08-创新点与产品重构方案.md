# 选墨集 / Sifted-Ink — 创新点与产品重构方案

> **日期**：2026-10-20　**定位**："规避雷区 + 与竞品不同 + 贴近真实需求"三者同时成立的创新点设计。
> **方法**：每条创新点必须同时绑定三件可查证的东西 —— ① 平台政策原文或公开实测数据 ② 选墨集现有代码位置 ③ 竞品缺口。绑定不上任何一项的，不叫创新点，叫许愿。
> **同时修正**：《00-总览与改造路线图》第七章 7.4 中"去 AI 味消痕"的建议**予以撤回**，理由见第一节。

---

## 〇、先撤回一个我上一轮给错的建议

我上一轮建议做"去 AI 味消痕 / 反检测"。拿到平台政策原文后，**这个建议是错的，两个原因**：

**原因一：方向踩线。**
番茄《关于加强低质内容治理公告》的四类严禁行为之首就是「**AI 粗制滥造**」，判定维度含「**是否批量生成**」「**是否严重缺乏原创性**」；起点 2026-04 公告反对「利用 AI 替代真人完成**核心内容产出**」。
一项专门帮用户把 AI 稿"洗得像人写的"的功能，**与平台的治理目标完全反向**——它不解决任何一条判定维度，只针对检测器。而检测器不是判定依据（平台还看逻辑断裂、文风突变、重复率、灌水）。

**原因二：技术上不成立。**
- 主流检测器把人类文本误判为 AI 的比例在 **10%–32%**（马里兰大学研究），同一篇纯手写稿在不同站点测出从个位数到 80+ 的结果
- 有研究显示**过度润色反而加重嫌疑**——被 copyedit 成"干净文风"的初稿比粗糙初稿更容易被标记
- 已进训练集的"反检测技巧"会**提高**被标记概率
- 检测依赖**困惑度**与**突发性**——这本质是"文本多样性"指标，把它包装成"降 AI 率"是概念偷换

**结论**：检测器的技术原理（困惑度/突发性/句长波动/短语重复）恰恰是一个**优秀的写作质量坐标系**。把它做成"节奏体检仪"（诊断"这章哪里像模板"）是可靠的、长期有效的、且零合规风险；做成"降 AI 率"是不可靠的、会被平台持续针对的、且是帮助用户欺骗平台的。

**所以本文的所有创新点，都建立在一个转换上：从"帮用户多产出"改为"帮用户在平台允许的边界内多产出，并且能证明自己合规"。**

## 一、雷区地图（分层 + 标注核实度）

### 第 1 层 · 平台已公开的判定维度 ✅官方可查

| # | 平台 | 官方原文口径 | 出处 |
|---|---|---|---|
| L1-1 | 番茄 | 四类严禁行为：**AI 粗制滥造 / 格式混乱 / 结构失常 / 空洞水文** | 番茄作家专区《低质治理公告》5/6/7 月 |
| L1-2 | 番茄 | 判定维度：**是否批量生成**、是否严重缺乏原创性、是否影响完整性与可读性 | 同上 |
| L1-3 | 番茄 | 处置梯度：拒签 → 减少分发 → 限制更新 → 下架整改 7/30 天 → 永久下架 | 同上 |
| L1-4 | 番茄 | 「**保留人工修改痕迹可作为申诉依据**」，申诉入口：作家助手 App → 帮助与反馈 → 人工咨询 | 作家助手帮助与反馈 |
| L1-5 | 起点 | 反对利用 AI「替代真人完成**核心内容产出**」；每月公示典型违规；持续升级 AI 检测识别 | 《关于进一步加强对非真人自动化创作管理力度的公告》2026-04 |
| L1-6 | 行业 | 16 家平台联合《网络文学行业反洗稿自律公约》，要求建立 AI 辅助创作使用规范 | 2026-04 |

### 第 2 层 · 广泛流传但**官方公告中查不到** ⚠️ 仅媒体/SEO 转述

| 说法 | 核实结果 |
|---|---|
| 「番茄要求 AI 辅助内容至少 30% 人工加工」 | **未在番茄官方公告体系中找到量化比例条款**。番茄采用**分类定性判定**（是否属"粗制滥造"），不是比例阈值 |
| 「起点要求作者申报 AI 使用范围」 | **未检索到公开的申报制度或申报表格**。实际是**事后检测 + 编辑复核 + 申诉** |
| 「另一平台 AI 含量 <20% 不统计、≥40% 拒稿」 | 未点名平台，来源为自媒体，不可引用 |
| 晋江「创意型只允许要素/粗纲级」/ 飞卢「签约禁止 AI 生成正文」 | 待《07-平台合规核实》确认 |

> **这条纪律很重要**：市面上流传最广的"30% 人工加工"恰恰查无官方依据。**把不确定的数字写进产品，等于给自己埋雷。** 所以下面所有设计只依赖 L1 层（官方可查）与可公开复现的实测指标。

### 第 3 层 · 著作权与合规 ⚠️

| # | 风险 | 现状 |
|---|---|---|
| L3-1 | **模仿在世作家**：`writing_style.json` 183 位中**仅 12 位标为公版**（`is_public_domain:true`），171 位（93.4%）非公版；`utils.py:431-440` 的写手提示词直接写「请模仿 **{作家名}** 的写作风格」并附带代表作名 | 最大的合规负债 |

## 二、重新定位（一句话）

> **从「多 Agent 小说生成器」改为「网文作者的合规产能放大器」——AI 负责大纲、设定、台账、节奏与体检，人负责核心内容与最终表达；工具全程留痕，让作者能证明自己站在平台允许的那一侧。**

**核心指标从「一次生成多少字」改为「作者采纳并改定了多少字」。**

**为什么这个定位有真实空位（不是自嗨）：**
- 笔灵：强在设定/伏笔台账 + 平台模板，但它是**代笔路线**（作者交付的是产品，不是自己的作品），闭源、订阅制、无合规留痕
- 豆包/通用模型：秒出但 >20 章设定漂移、只给片段、零网文规范、零留痕
- InkOS：多 Agent 审计 + `style analyze` / `detect --all` / `revise --mode anti-detect`，**但它做的是"反检测"**，且是英文/技术向生态，AGPL
- oh-story-claudecode：13 项中文网文技能包 + 147 行 AI 味禁用词表，**质量很高但无 UI、无状态、无平台对接**，且它的 story-deslop 走的正是"去 AI 味"路线
- 平台自家 AI：审核对口，但**只能站内用**，出了平台什么都做不了

**没有任何一家在做「平台合规 + 人在环 + 留痕 + 本地私有」。** 这是真空白。

## 三、五个创新点

### 创新点 1 · 单线人在环：把「批量生成」这条判定维度**直接拆掉**

| | |
|---|---|
| **痛点来源** | 番茄判定维度明文含「是否批量生成」。选墨集当前形态恰好**最像批量生成**：500 版本 × 30 章 × 20 分钟一键出书。这是产品自己撞自己的枪。 |
| **现有代码基础** | `preactor.py:693-701` 的多版本 `asyncio.gather`；`preactor.py:34-516` 的 `run_version` 已按章节迭代（`state.chapter_count` 循环），**逐章循环本来就在**，只是外面套了"跑 N 版 × M 章"的批量壳 |
| **竞品缺口** | 所有竞品都在卷"更快更多"：豆包秒出、笔灵批量、选墨集 500 版本。**做"少而准、每章人在环"的是空的。** |
| **机制设计** | ① 默认 `num_versions=1`、**章节级 checkpoint**，每章结束落盘并**停下来等人**；② Web UI 出「本章已生成 → 编辑 → 采纳 / 重写本章 / 续写下一章」三选一；③ 每次采纳记录 diff；④ 把「一次一章」做成**默认**，把批量做成显式的高级选项（并警告它触碰 L1-2 判定维度） |
| **为什么这解决雷区** | 判定维度"是否批量生成"直接变成"否"；"是否缺乏原创性"变成"每章都有人工编辑轨迹"；"是否影响完整性与可读性"变成"每章被人工过了一遍" |
| **工作量** | 中等（Web UI 一章一屏 + diff + checkpoint 落盘 + 事件改造）。**复用已有的 `preactor.py` 章节循环，不动核心算法。** |
| **验证方法（先验证再投入）** | 找 5 位真实网文作者（豆瓣网文/知乎/起点作者群）看 2 个 demo 截图，测一个问题：「如果每章必须你点一次采纳，你还会用吗？为什么？」——若 5 人中 <3 人说会，就放弃这条。**半天能验证。** |
| **风险** | 用户嫌慢。缓解：单章 800-1500 字只需 30-60 秒，比"等 20 分钟"反而更可控。 |

### 创新点 2 · 创作过程档案：把「人工修改痕迹」变成**自动产物**

| | |
|---|---|
| **痛点来源** | 番茄官方明写「**保留人工修改痕迹可作为申诉依据**」；起点是事后检测 + 编辑复核 + 申诉。**作者现在没有任何工具帮他们留痕**——改完就没了，申诉时无法举证。 |
| **现有代码基础** | ① `webui/app.py:75` 的 `runs` 已存 `result`/`config`/`eval_path`，有章节级数据；② `exporter.py` 已有多格式导出管线；③ `preactor.py` 的 `state` 已有 `chapters`、`total_words`、每章 `content`/`chapter_title` |
| **竞品缺口** | 笔灵有站内自动存稿（保内容），但**没有"这份内容里多少是人写的"这份记录**；通用模型完全不存；oh-story-claudecode 是技能包，天然无状态。**"人机分工比例的证据链"无人提供。** |
| **机制设计** | 每个字符带来源标记（`ai` / `human` / `human-edited`），逐章统计：AI 产出字数、人工新增字数、人工改写比例、编辑操作次数与时间戳。→ 一键导出 **《创作过程档案》**（Markdown + CSV），字段对齐平台申诉所需的"修改轨迹"。再叠加一个**风险提示**：某章人工改写比例明显低于全书均值时给出提醒。 |
| **合规性** | ⚠️ 注意：这**不是**"帮你伪装成人写的"，而是"如实记录人机分工"。平台要的恰恰是这个——**声明真实的使用范围**。这与"反检测"有本质区别：我们不隐藏 AI 参与，我们证明人在哪里参与。 |
| **工作量** | 小-中（新增一张 `chapter_provenance` 表 + diff 记录 + 导出器）。**不改生成逻辑。** |
| **验证方法** | 查作者圈的真实申诉场景：被拒签/限流后，作者实际上是怎么举证"我有大量人工修改"的？访谈 3-5 人。**如果他们根本没这个需求（因为很少人走到申诉），这条降级为 P1。** |
| **风险** | 若是"必须申报"制被平台真正落地，这条价值直线上升；若是纯事后检测，价值存在但没那么刚性。**《07-平台合规核实》会给出第 5 问的确切答案**（平台是否真有申报入口、要填什么字段）。 |

### 创新点 3 · 手法库取代作家模仿：把最大的著作权雷区**变成知识资产**

| | |
|---|---|
| **痛点来源** | 183 位作家仅 12 位公版；`utils.py:431-440` 直接让模型「模仿 {作家名}」并给代表作。**这是整个项目最大的法律负债，而它恰好是最大的营销卖点。** |
| **法律依据** | 著作权保护**具体表达**，不保护创作方法与风格本身（思想表达二分法）。「悬念前置 + 身份反转 + 群像速写」是**方法**；「XX 某年某月某日的具体句子」才是**表达**。这个区分在中国《著作权法》框架下站得住。 |
| **现有代码基础** | `writing_style.json` 已有 `name/region/style/representative_works/death_year/is_public_domain` 结构，**只需加字段**；`utils.py:477-482` 的 `is_author_public_domain` 已是现成钩子 |
| **竞品缺口** | 所有竞品要么没有作家库，要么也在模仿。**只有选墨集手里有 183 位作家的元数据库**——只有它能完成"作家 → 可执行手法"的转换。**这是别人抄不走的护城河。** |
| **机制设计** | ① 每条新增 `techniques: [5 个可执行手法]`、`avoid: [不可模仿的具体元素：其标志性句式/专属意象/人物原型]`、`risk_tier: public_domain / classic / modern / living`、`pd_jurisdiction`（三岛由纪夫 1970，按日本法 2065 年作品到 2035 才公版）；② `utils.py:431-440` 的提示词从「模仿 {name}」改为「使用以下手法：…；严格避免：…」；③ **用户自己的风格指纹**：贴 3 段自己的文字 → 提取句长 p50/p90、对话率、标点节奏、3-gram 重复率 → 逐章对齐（零版权风险，且是检测研究里公认"最有效的长期方案"） |
| **工作量** | 中（183 条数据改造 + 提示词改造 + 指纹提取器）。**数据改造可半自动：先用 LLM 把 183 条 `style` 批量转成 techniques 草案，再人工抽检 20%。** |
| **验证方法** | A/B：同一故事，`style` 原文 vs 手法规格，各生成 3 章，**盲评**（作者 5 人打分：像不像那个作家 / 读感）。若手法版读感不劣，就证明参数化不损失效果——**这是"手法库"能否成立的前提**。 |
| **风险** | 手法化后可能失去"像某某"的辨识度 → 对追求"神似某作家"的作者是减分。**但这类作者本就处在 L3-1 风险里，工具应当明确劝退而非纵容。** 把它做成"推荐用你自己的身体"，是价值主张的升级而非缩水。 |

### 创新点 4 · 文本多样性诊断仪：把不可靠的「AI 率」换成**可靠的质量坐标系**

| | |
|---|---|
| **痛点来源** | 社区共识痛点第 3 位是「AI 味 / 同质化」；但**没有任何工具给出可验证的分数**——全是"请不要有 AI 味"这种无效指令（研究共识：AI 只认具体禁令和替换规则；约束条数 ≤6 条最稳，再多反而事实错误上升）。 |
| **现有代码基础** | `utils.py:66-110` 已有 `text_similarity`；`utils.py:447-474` 已有 `moderate_content` 的"扫描-返回-hits"结构，**同样的骨架可直接复用** |
| **竞品缺口** | oh-story-claudecode 有 147 行禁用词表（Gate A 必查），但那是**黑名单**（命中即失败），不是**诊断**（告诉你哪里像模板、为什么）；InkOS 有 `detect --all`，面向英文技术向；国内工具无一提供中文网文的**可解释**诊断 |
| **机制设计** | 按可复现的 8 维指标输出**逐章诊断卡**（不是"AI 率 XX%"，而是可解释的维度分 + 定位）：<br>① 短语重复率 ② 句长波动（均值/标准差/长句短句比） ③ 词汇多样性 ④ 标点节奏（逗号密度/破折号/冒号标题/引号样式） ⑤ 对话率 ⑥ 情绪密度 ⑦ 语义平滑度 ⑧ 3-gram 重复率<br>**每项配「本卷基线对比」**（跟这本书自己前 20 章比，而不是跟全网比）——这样它测的是"这章是不是像模板"，而不是"这章像不像 AI" |
| **为什么这不踩线** | 它是**写作质量工具**：句长波动低 = 节奏单调；短语重复高 = 用词贫乏；对话率低 = 叙述腔过重。这些**与是否用了 AI 无关**，与作者是不是人也无关。**不承诺"降 AI 率"，因此不会被平台政策针对，也不依赖检测器的黑盒。** |
| **差异化** | 竞品的"去 AI 味"是**承诺**（降多少），选墨集的是**坐标**（现在在哪、往哪走）。前者不可信且易过时，后者永远成立。 |
| **工作量** | 小-中（一个纯函数模块 + 一张诊断卡 UI）。**纯规则，无 LLM 调用，零 token 成本。** |
| **验证方法** | 取 30 段真实网文（人工写的）跑本诊断器，看它能否把"AI 味最重"的那几段排出来。**若分不出，就是指标选错了，指标必须先在这 30 段上验证再上线。** |
| **风险** | 维度权重无公开标准 → 必须自建基线并公开方法论，让用户能质疑。**这本身是信任资产。** |

### 创新点 5 · 走向树 + 后果推演：让「多 Agent」从一个**噱头**变成**刚需**

| | |
|---|---|
| **痛点来源** | 社区评测里**排第一**的痛点是"卡文"（救急/给备选走向）。但所有工具给的走向建议都是**黑盒**——豆包给 3 个续写、笔灵给建议，作者无法判断"走这条会不会写崩"。 |
| **现有代码基础** | 🎯 `prompts.py:134-138` **导演已经在输出 `branch_choice` 与 `branch_options`**（目前只有 2 个选项、只有一句 description）——**但全仓无任何一处消费它**。这是**现成的钩子**，复活成本极低。 |
| **竞品缺口** | 通用模型：给续写（黑盒、局部、不知道后果）<br>笔灵：给走向建议（黑盒）<br>选墨集有多 Agent 预演能力 → **唯一能推演"走这条路的下游后果"** |
| **机制设计** | 把 `branch_options` 从 `[{"id","description"}]` 升级为**带推演的岔路口卡片**：<br>每条走向标注 —— **爽点密度**（本章能兑现几个爽点）· **伏笔代价**（种下什么、回收周期）· **设定冲突**（与已有设定/人物状态相冲的地方）· **预计章数到转折** · **崩坏风险**（低/中/高，附理由）· **和另一条走向的差异点**<br>作者点选一条 → 该走向成为后续章节的约束条件（真正生效，写进 `state`） |
| **为什么这让 500 版本有意义** | 当前 500 版的价值是"多花 167 倍的钱换 +0.8~1.5 分"（期望最大值随 log N 增长，边际成本 ≈¥2,800/分）。<br>**但"探路"的价值不是择优，是覆盖。** 5 个带推演的岔路口 = 5 次"这条路的下游会怎样"的高质量判断——**这才是多版本预演唯一成立的用途**。因此建议：`num_versions` 语义从"并行生成 N 份成品"改为"**并行推演 N 条走向**"，成本结构完全不同（推演不需要写完整正文）。 |
| **工作量** | 中（`prompts.py` 扩字段 + 一张走向选择 UI + 选中的走向写回 `state` 约束） |
| **验证方法** | 找 10 个真实卡文案例，把走向树 + 推演结果给他们看，测："这个推演信息对你有帮助吗？会不会改变你的选择？"——**一周可验证。** |
| **风险** | 推演本身是 LLM 预测，可能说得头头是道但不准。**必须让推演可被证伪**：每条走向在选完之后，跑 1 章验证并回填"实际爽点密度 vs 预测"。**能自我纠错的推演才有价值。** |

## 四、五个创新点如何叠加成一个完整产品

```

  创新点 5           │  走向树 + 后果推演                        │  ← 卡文（第一痛点）

  （协作）           │  每章都留 diff                             │
                     └───────────────┬──────────────────────────┘
                                     │
        ┌────────────────────────────┼────────────────────────────┐
        │                            │                            │
┌───────▼────────┐        ┌──────────▼─────────┐        ┌─────────▼────────┐
│ 创新点 3       │        │ 创新点 4           │        │ 创新点 2         │
```

## 六、明确不做（写死，防止路线跑偏）

| ❌ 不做 | 为什么 |
|---|---|
| "降 AI 率" / "过检测" 功能 | 方向踩 L1-1/L1-2，技术不可靠（误判 10-32%），且技巧会随检测器升级失效 |
| 提高 `num_versions` 上限 / 更高并发 | 直接撞 L1-2「是否批量生成」，且成本边际极差 |
| 加更多作家风格条目 | 放大 L3-1 著作权负债；183 条已足够做手法库 |
| 加更多模型供应商 | 13 家已过剩，痛点是装不上用不起 |
| 模拟特定在世作家的"文风" | 不删作家条目，但**提示词里不再出现作家名**（创新点 3） |
| 自动生成"投稿用"承诺性文本 | 只如实记录，不代写声明 |

## 七、MVP 排序（按"验证成本 / 收益"排，不按实现难度排）

| 序 | 事项 | 依赖 | 成本 | 验收 |
|---|---|---|---|---|
| **M0** | **先做验证，不写代码**：10 位作者访谈 + 30 段真实网文跑诊断指标 + 5 份盲评 A/B | 无 | 3 天 | 三个 go/no-go 结论 |
| **M1** | 创新点 4 文本多样性诊断（纯函数、零 token） | M0 指标验证 | 1 周 | 30 段真实网文上排序合理 |
| **M2** | 创新点 3 手法库：183 条数据改造 + 提示词从"模仿"改"手法" | M0 盲评 | 1-2 周 | 手法版盲评读感不劣于原版 |
| **M3** | 创新点 1 单线人在环：逐章 checkpoint + 编辑/采纳/重写 | M1 | 2 周 | 一章一屏；取消不丢稿 |
| **M4** | 创新点 2 创作过程档案 + 导出 | M3 | 1 周 | 可导出可核对的分工记录 |
| **M5** | 创新点 5 走向树 + 推演（`prompts.py:134-138` 复活） | M3 | 2 周 | 走向被选后真的约束后文；推演可回填验证 |
| **M6** | 平台档案（番茄/起点/七猫/盐言）+ 体检报告合并 | M1+M4 | 1-2 周 | 一份《投稿前体检表》 |

> **M0 是最重要的投资**：3 天的验证能避免 6 周的错误方向。三个 go/no-go：
> ① 作者愿不愿意"每章点一次采纳"？（决定创新点 1）
> ② 手法规格的读感是否不劣于直接模仿？（决定创新点 3）
> ③ 8 维诊断指标能否在真实网文上区分出"AI 味重"的段落？（决定创新点 4）

## 八、自我反驳（我的方案哪里可能错）

| 质疑 | 我的回应 | 但如果质疑成立 |
|---|---|---|
| "合规留痕"会不会是伪需求——作者根本不会走到申诉那一步？ | 番茄处罚量级是每月拒签 10 万+ 本、7 月拒签 16 万本，**被处置的人很多**。留痕的价值在**被处置之后**才显现，属于"平时无用、出事救命" | 若 M0 访谈证实几乎无人申诉 → 创新点 2 降级为 P2，**先做 M1/M3** |
| "每章人在环"会不会把用户吓跑？ | 用户现在等 20 分钟还不知道结果；逐章反而更可控。**但这是产品价值观的转向，得诚实测试** | 若 5 人中 <3 人接受 → 保留批量为高级选项，**不强行改默认** |
| "不做降 AI 率"会不会被竞品比下去？ | 降 AI 率是**红海且注定过时**（技巧进训练集→失效→再更新）。文本多样性诊断是**永久成立的写作质量坐标系** | 若用户强烈要 → 只能作为**私有实验功能**标注风险，不能进主推 |
| 手法库会不会"把作家做小"？ | 手法化丢掉的是**辨识度**，而辨识度来自具体表达——那正是著作权风险所在。**这是取舍，不是退步** | 若盲评显示手法版明显不如模仿版 → 只能转推公版作家（12 位）并明确"非公版不支持模仿" |
| 平台政策 3 个月一变，档案会不会过期？ | 是。所以**平台档案必须是带日期的、带来源链接的、用户可自行更新的社区数据**，不是硬编码 | 需要做"档案更新"轻机制（issue 提 PR 更新 + 版本号） |
| 五个创新点会不会太多？ | 它们不是五个功能，是**同一条流水线上的五个环节**：决策(5) → 协作(1) → 表达(3) → 体检(4) → 留痕(2)。**必须一起才闭环**，所以 M0 验证后按 M1→M5 串行推进，不并行铺开 |

## 十、需要你拍板的三个问题

1. **是否接受"默认不再一键出整本"？** 这是创新点 1 的前提，也意味着要弱化"一键出书"这个最响亮的宣传点。**我的判断：必须接受**——因为"是否批量生成"是番茄明文的第一条判定维度，继续主打一键出书等于产品自己在撞枪。
2. **是否接受"提示词里不再出现作家名"？** 这会让"模仿张爱玲"变成"使用张爱玲常用的 5 个手法"。**我的判断：必须接受**——183 条里 171 条非公版，现在的写法是把最大的法律风险挂在最显眼的卖点上。
3. **是否先花 3 天做 M0 验证，再动代码？** **我的判断：应该先验证**。五个创新点里有三个（M1 指标、M3 手法、M1 人环）的成败取决于真实作者的反应，而这可以在 3 天内测出来，比做完 6 周再发现方向错要划算得多。
