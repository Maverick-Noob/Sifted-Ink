## 二、一句话诊断

> **这不是一个"写得烂"的项目，是一个"跑得起来但账算不清、承诺兑现不了、没人敢改"的项目。**
>
> 核心算法（大纲 → 章节 → 写手 → 评估）的骨架是对的，分层单向、领域模型干净、文档齐全、审美在线——这些是真实资产。
> 但它同时具备三个致命特征：
> 1. **承诺与实现脱节**——README 描述的是"理想中的产品"，代码是"当时的实现"，两套并存；
> 2. **账算不清**——token 少算 3.7 倍、版本数无上限、每次刷新重生成前附文，用户对花费零掌控感；
> 3. **静默失效**——一批不报错、不告警的缺陷，让结果"慢慢变差"，用户只感受到"生成质量差"却无从定位。
>
> 而"bug 不少"的感受，主要来自第三类——**它们比崩溃更伤，因为崩溃会告诉你，坏结果只会让你怀疑 AI。**

## 三、三个决定性发现（这三条决定改造方向）

### 发现 1 · "500 条情节线"在代码里并不存在 ❌

README:50 是全项目的第一卖点：*"每条情节线在关键分支点上做出不同选择，探索故事的各种可能性。"*

代码事实：
- 导演被要求输出 `branch_choice` / `branch_options`（`prompts.py:134-138`），**全仓无任何一处消费**（仅在 prompt 文本和 `agents.py:791` 的兜底字典里出现）。→ 分支从未生效。
- 每个版本**各自生成 3 份大纲并各自择一**（`preactor.py:130-181`）→ 3 个版本面对同样 3 个角度，**大概率挑中同一份大纲**。→ 3 倍的钱换 3 条同质线。
- 自动结局写回**共享的** `config.story_end`（`preactor.py:118-126`，且 `preactor.py:696` 把同一个 config 对象传给所有并发版本）→ 所有版本被强制收敛到**同一个结局**，"探索不同结局"不存在。

**结论：版本间的差异 100% 来自温度随机性，不是来自设计。** 这意味着当前**唯一**的多样性来源是"多花 167 倍的钱"。

### 发现 2 · 理论产能上限 ≈ 4.5 万字，做不了网文 ⚠️

`preactor.py:552` 把每章字数硬顶在 **1500 字**，`max_chapters` 默认 **30** → 理论产出 **≤ 45,000 字**。

对照市场真实口径（国内社区与平台规范实测）：
| 平台 | 体量 | 单章字数 |
|---|---|---|
| 番茄小说 | 10–50 万字 | 2000–3000 字 |
| 起点中文网 | 100 万字+ | 2000–3000 字 |
| 知乎盐选 | 1–3 万字 | — |

**当前架构做不了番茄，更别提起点。** 而用户若把"目标字数"填成 30 万，会被**静默截断到 15%**，界面上零提示。
同时 `agents.py:1055` 硬编"每章 500-800 字"，而国内共识是 2000-3000 字/章——**单章体量本身就比市场小 3-4 倍**。

### 发现 3 · 效果好坏与"多 Agent"无关，与"少做的几件事"有关 🎯

算一笔账：单版本 15 章 ≈ **285K token / 90 次调用**；3 版本 ≈ 855K token。
而单 Agent 流水线（1 次大纲 + 15 次写手 + 1 次评估）≈ **80K token / 17 次调用**。
**当前架构产出 3 个版本的代价 ≈ 单 Agent 架构产出 9 个版本。**

写手最终只消费导演的 `scene_setting` / `chapter_summary` 两段文本（`agents.py:1076-1155`）——**主角和 NPC Agent 花调用产出的 500-800 字决策被重写成 650 字正文。若让写手直接读那两段文本，可写出同样的章节。**

真正决定"好不好看"的东西，恰恰**一个都没做**：
- 主角 / NPC / 导演三方互不可见 → 对话各说各话，写手被迫转述 → **"转述腔"就是 AI 味的主因**（`agents.py:855-882,896-948`）
- 重复检测触发时把**固定 7 条模板**（含"突然，一道闪电劈开了天空"）原样注入正文 → **系统在主动生产 AI 味**（`preactor.py:653-660`）
- 评估器用绝对分、无锚点、泄漏版本 ID、单次采样、5% 阈值在 0-10 制上仅 0.4 分 → **几乎必然落入"分数接近"分支**（`agents.py:962-1007`）
- 写作风格库 183 条描述 **80% 是形容词堆砌**（"以冷峻犀利的笔触解剖国民性"）→ **选了鲁迅和选了海明威，生成出来几乎一样**

## 四、改造主线：三段式

```
第一段 · 止血（0-3 周）   让它从"能跑但坏"变成"能跑且对"
   目标：修掉 4 个 P0 + 5 个"静默失效"高危项，让 README 不再骗人
   成本：约 150 行代码 + 3 段提示词改写 + 9 处文档对齐
   验收：默认配置跑通不报错；同一 story 跑 3 次结果结构稳定；token 实测与显示一致

第二段 · 立信（3-8 周）   让陌生人敢用、敢投钱
   目标：成本可见 + 不丢稿 + 一键装 + 有 CI/测试 + 密钥安全
   成本：pyproject + extras + 锁文件 + CI + 20 个单测 + 持久化 + 桌面端 exe
   验收：`pip install .` 可用；exe 双击能跑；有 CI；成本预估误差 <15%；取消不丢稿

第三段 · 换心（2-6 月）   从"一键出整本"转向"情节决策台 + 章节工作台"
   目标：让"多 Agent"名副其实、让大纲/设定成为用户资产、接入平台规范
   成本：编排层重构 + Web UI 重做 + 风格库数据化
   验收：branch_options 可点选并真的改变后续；大纲可编辑可锁定；支持番茄/起点字数与钩子规范
```

## 七、第三段 · 换心清单（战略层）

### 7.1 让"多 Agent"名副其实（不是加 Agent，是让现有 Agent 真的对话）

```
现在：Director ──写──▶ Protagonist ──写──▶ NPC ──写──▶ Writer     （三方互不可见）
改后：Director ──▶ Protagonist ──▶ NPC ──▶ Writer                （台词原文逐级传递）
      + 大纲竞优提升为「全局只做一次，所有版本共用」
      + 版本差异改由显式旋钮产生（叙事密度 / 冲突焦点 / 结局处理），而非靠温度碰运气
```

- **成本目标**：每章 6~7 次调用 → **2 次**（导演+写手，把主角/NPC 的决策降级为写手 prompt 内的结构化字段），省 **50-70% token**。
- **诚实说明**：砍掉独立主角/NPC Agent 会损失角色自主性带来的多样性。正确做法是降级为可选的 `quality_mode="full"`，并**先做同预算 A/B 实测**——目前**没有任何证据支持"多 Agent 提升质量"这一宣称**。

### 7.2 从"一键出整本"转向"情节决策台 + 章节工作台"

**推翻 3 项**（继续做只会加深"代笔"印象，且与市场共识"核心创意、大纲节奏、人物声音必须自己掌握"冲突）：
1. 自动择优 → **唯一赢家** 改为 **人工择版**（并排 3 条线 + 各自梗概/首章/分数）
2. 一次运行 = 一整本书 → 改为**可编辑的稿段**
3. 无状态一次性执行 → **持久化 + 续跑 + checkpoint**

**保留 6 项**（做得不错，别动）：多 Agent 分工 · RAG 故事记忆 · 三幕节奏控制 · 183 作家风格库 + 公版标注 · 起名引擎 · 多格式导出 + 13 家供应商。

**改造 5 项**：分支真正生效并可点选 · 大纲/设定变用户资产 · 四维评估降级为**体检报告**（加"钩子质量""AI 味指数"）· 运行前必见成本与时长 · 导出与文档对齐。

### 7.3 补上三块"写之中"和"写之后"的能力（当前 100% 空白）

| 能力 | 为什么是刚需 | 最小实现 |
|---|---|---|
| **章节级重写 / 续写 / 局部改** | 最高频真实需求；当前只能整本重跑（≈¥28 一次） | 结果页每章加"重写本章 / 续写下一章 / 改这段"，单章级 ≈ ¥0.15 |
| **可编辑大纲 + 设定集 + 人物卡** | 市场共识："设定必须自己掌握" | 大纲从 JSON 渲染成可编辑列表并锁定；`user_npcs` 升级为完整人物卡 |
| **伏笔台账 + 一致性检查** | "第 30 章崩坏墙"是长篇最大杀手 | `PlotLoop{id, 文本, 埋设章, 优先级, 状态, 应收章}`；每章输出 `loops_resolved`，逾期必须显式 abandon |

### 7.4 接入平台规范 + 去 AI 味（零 token 成本，收益最大）

- **平台模板**：番茄 / 七猫 / 盐言的黄金三章、章末钩子、爽点密度（每 800 字一个小爽点）、章节字数（2000-3000）
- **去 AI 味**：⚠️ **本条已于同日修订并撤回**，见《08-创新点与产品重构方案》〇节。平台已把「AI 粗制滥造」列为四类严禁行为之首，做"降 AI 率"既踩线又不可靠（人类文本误判率 10-32%）。**替代方案是创新点 4「文本多样性诊断仪」**——同一套技术指标（困惑度/突发性/句长波动/短语重复），但定位为写作质量诊断而非反检测，零合规风险且长期有效
- **写作风格库数据化**：183 条形容词堆砌 → **可执行风格规格**（叙事人称 / 视角距离 / 句长 p50·p90 / 对话率 / 描写与心理预算 / 意象偏好 / **禁用词** / **自撰 150 字样例**）
  > 参数给方向，**样例给手感**——这是整个改造里性价比最高的一项数据工作。

## 八、定位建议（结合竞品调研）

### 现状
- **它现在是什么**：自托管的多 Agent 短篇批量生成器——技术上做得不错、文档全、审美在线，但**没有任何"创作"环节**。
- **它应该是什么**：面向中文网文作者的「**情节决策 + 章节工作台**」；核心指标从"一次生成多少字"变为"**作者写了/改了多少字**"。

### 三方案对比

| | **A 情节决策台** | **B 合规风格引擎** | **C 分支叙事引擎** |
|---|---|---|---|
| 用户 | 网文签约作者 | 签约作者 / 盐选写手 | 互动小说作者 |
| 核心 | 可点选的走向 + 章节走向树 + 设定/伏笔 + 平台导出 | 平台模板 + 去 AI 味 + 风格规格 + AI 味体检 | 真·剧情分支树 + 单支线导出 |
| 工程量 | 中 | 中 | 中（`branch_options` 是现成钩子） |
| 差异化 | 中（InkOS 压力大） | **高**（合规是无人愿意做的脏活） | **高**（几乎无人做） |
| 合规风险 | 低 | **正向**（把最大雷区变成护城河） | 低 |

### 推荐
**主线走 B（合规风格引擎），并把 C（分支）作为差异化彩蛋并入，A 作为交互骨架。**

理由：
1. B 把当前**最大的合规雷区**（183 位中 171 位非公版、66 位在世中文网文作家可直接模仿）**转成最强差异化**。国内著作权实践不承认"风格不受保护"的免责路径，单纯靠免责声明是责任转移、不是风险控制。
2. C 让"多 Agent 预演"这个概念**名副其实**——500 条预演的价值在"探路"而非"择优"，且 `branch_options` 已在代码里，只是下游从未消费。
3. 竞品警告：主打"多 Agent + 评估择优"的方向，**InkOS（~10.3k star，AGPL-3.0）已用"真相文件 + 多 Agent 审计"做得更成熟**。继续以这个做核心叙事，等于正面撞上一个体量更大、已有口碑的项目，而自己还没有社区。**换叙事比换功能重要。**

### 明确不要做 ❌
- **不要**再加"更多作家风格 / 更多导出格式 / 更高版本数上限"——都是加法，不改变范式天花板，还放大合规风险与成本
- **不要**再加"更多模型供应商"——13 家已过剩，真正的痛点是**装不上、用不起**
- **不要**把 `num_versions` 上限从 500 往上提——500 版 ≈ 6.3 万次调用 / 1.1 亿 token / ≈¥4,280，而产出仍是**一部 1.2 万字小说**；best-of-N 的期望最大值在 0-10 制上从 N=3 到 N=500 只换来 **+0.8~1.5 分**，边际成本 ≈ **¥2,800/分**。建议 **`num_versions ≤ 5`**，预算转投"深写 + 修订 + 评估重采样"。

## 十一、给项目所有者的一句话建议

**先别急着加功能。** 现在的选墨集，用户第一次打开会撞上"照抄 README 跑不起来"、"TERMS 说 MIT"、"Issues 链接点不开"；跑起来之后会撞上"等 20 分钟没反馈"、"取消全丢"、"不知道花了多少钱"、"情节摘要是空的"、"MOBI 导不出来"。
