# 选墨集 / Sifted-Ink — 竞品与市场定位

> 本报告由主会话基于公开可访问的国内源检索 + 源码事实核对写成（竞品调研子代理因 API 额度中断，由主会话接手）。
> 检索时间：2026-10-20。检索源以国内可访问站点为主（CSDN / 博客园 / 知乎 / 头条 / 搜狐 / 什么值得买 / 少数派 / GitHub）。
> 说明：多数「AI 写小说工具横评」类文章为软文（部分站点已自标「商业推广」），结论需交叉验证，已在文中标注可信度。

## 0. 一句话结论

**选墨集现在做的是「批量生成短篇」，而市场真实付费场景是「辅助长篇连载」；竞品早已用「工作台 + 一致性台账 + 平台模板」吃掉了这个位，而选墨集最强的差异化资产（183 位作家风格库 + 公版合规标注）反而不在主卖点的叙事里。**

### 差距总结（三句话）

1. **选墨集在"写之前"全线空白**：没有可编辑的大纲、没有设定集、没有伏笔台账、没有章节级重写。所有对标产品都把创作控制权交还给人——这恰好是市场共识（"核心创意、大纲节奏、人物声音必须自己掌握"）。
2. **选墨集在"写之中"缺平台规范**：番茄/七猫/盐言模板、黄金三章、章末钩子、爽点密度、平台字数规范——这正是网文作者的付费考核项。
3. **选墨集在"写之后"缺兜底**：自动存稿、断点续跑、失败重试、真实成本计量——这正是"等 20 分钟结果全丢"这类事故的解药。

## 3. 真实痛点排序（基于国内社区讨论，2026）

| 排名 | 痛点 | 社区原话/依据 | 选墨集是否解决 |
|:--:|---|---|:--:|
| 1 | **卡文** | 几乎所有横评把"卡文救急/给备选走向"列为第一需求 | ⚠️ 勉强——但 500 条预演恰恰是"最笨的解法" |
| 2 | **长篇崩坏**（人设矛盾、伏笔遗忘、时间线错乱） | "第 30 章左右是崩坏墙"；>20 章设定漂移 | ❌ 章节上限 30、每章上限 1500 字，**结构上就不可能撑过长篇** |
| 3 | **AI 味 / 同质化** | "他说得很有道理，但是……"式端水句；"此外/综上所述/不禁感叹"满天飞 | ❌ 无去 AI 味机制，提示词反而是通用文学腔 |
| 4 | **爽感与商业节奏** | 黄金三章、付费卡点、章末钩子；每 800 字一个小爽点 | ❌ 完全没有 |
| 5 | **稿件丢失** | 笔灵站内自动存稿被反复夸赞 | ❌ 取消/失败即全丢，无历史、无续跑 |
| 6 | **平台审核风险** | 纯 AI 正文难签约、平台有 AI 检测 | ⚠️ 有敏感词过滤（不阻断），但无平台规范适配 |
| 7 | **成本失控** | 一次长篇生成直接烧掉整月额度 | ❌ 无预估、无真实计量，估算还低 3 倍 |

**市场空位判断（明确结论）：**
「并行预演 500 条情节线」在真实需求排序中**排不进前 5**。它服务的是"内容工作室批量出短篇"，不是"网文作者日更"。这不是伪需求（对短故事号/公众号矩阵确实成立），但**是一个更小、更 B 端的市场**，且已被 InkOS、NovelForge 等开源项目以更高工程完成度占据。

## 4. 差异化定位建议（3 选 1）

### 方案 A ·「中文网文合规风格引擎」（推荐主线）

- **目标用户**：签约网文作者、公众号/知乎盐选写手、自媒体故事号
- **最痛场景**：已有平台规范压力，需要"不掉链子、不撞 AI 检测、字数/钩子合规"的成稿
- **核心功能**：把 183 作家风格库从"形容词堆砌"升级为**可执行风格规格**（句长分布/叙事人称/视角距离/对话率/意象偏好/禁用词）；内置番茄/七猫/盐言**平台模板**；**去 AI 味消痕**（具体禁令 + 替换规则，不是"不要有 AI 味"）；**AI 味体检报告**
- **护城河**：唯一把"风格 + 合规"做成结构化数据资产的开源项目；合规数据（公版判定）无人愿意维护
- **取舍**：放弃"一键出整本"的叙事；放弃"更像某作家"的卖点，改成"更不像任何作家但更像合格网文"
- **为什么值得做**：83% 的作家库是非公版（171/183），在世作家模仿在国内平台是有真实法律与平台双重风险的功能——把它**收窄成"合规风格规格"**，反而把最大的合规雷区变成了最大的差异化

### 方案 B ·「互动分支叙事引擎」

- **目标用户**：互动小说作者、游戏/视觉小说编剧、有声剧脚本作者
- **最痛场景**：需要一棵**真的分叉的剧情树**（每章 2-4 个分支，通向不同结局）
- **核心功能**：把 `branch_options` 从死代码复活为**一等公民**；分支树可视化编辑；单支线独立导出；分支投票/读者互动数据回流
- **护城河**：选墨集代码里**已经有导演分支的提示词和解析，只是下游从未消费**——改造量比从零做小
- **取舍**：市场更小（互动小说/游戏在中国是细分市场），但**几乎无人做**，竞争密度最低
- **额外价值**：这是唯一能让"多 Agent 预演"这个概念**名副其实**的形态——500 条预演的价值在"探路"而非"择优"

### 方案 C ·「本地私有化 AI 写作工作台」

- **目标用户**：不愿把内容发给闭源 SaaS 的作者/工作室/企业内部内容团队
- **最痛场景**：数据不出本地、模型可自选（Ollama/本地权重）、可审计
- **核心功能**：Ollama/本地模型一等支持；项目文件（人物卡/大纲/章节）本地文件系统化；可审计的 token 账；一键导出"可编辑工程包"（Markdown + 人物卡 JSON + 大纲 JSON）
- **护城河**：弱——SillyTavern/AI_NovelGenerator 都已占位
- **取舍**：低天花板，适合作为**基础设施而非定位**

### 推荐路径

**主线选 A（合规风格引擎）**，把 **B（分支引擎）作为差异化彩蛋**并入（因为 `branch_options` 已经是现成的实现钩子），C 作为默认交付形态。

理由：A 是唯一"既解决真实痛点（AI 味 + 平台规范）、又用上现有最强资产（风格库）、又能规避最大合规风险（在世作家模仿）"的定位。B 不需要新市场教育，且能让多 Agent 概念真正成立。

## 5. 合规与商业化

### 版权风险（**这是当前项目最被低估的雷**）

- 选墨集风格库 183 位中**仅 12 位标记为公版**（`is_public_domain: true`），即 **171 位（93.4%）** 为在世或去世不足 50 年的作者，包括"网文大神"66 位。
- README:184 / TERMS.md:29 均宣称"公版优先""界面会标注风险提示"——**标注做了，但 93% 的库是 🟡**，等于形式合规、实质失衡。
- 中国著作权法保护作者的**署名权、改编权、保护作品完整权**，风格模仿不天然免责；美国 `Andersen v. Stability AI` 一类的"风格不被版权保护"结论**不适用于中国**。中国实践中更常见的是"实质性相似 + 可接触性"的认定路径。
- **建议动作**：① 收缩为"公版 + 结构化风格规格"，非公版作家条目改为**"风格特征标签"**（如"冷峻讽刺的社会派笔法"）而非"模仿 X 本人"；② 在文生成前强制"风格规格"而非"作家名"进入提示词；③ 在 UI 上把"在世作家"分区折叠默认收起；④ TERMS 补充中国大陆法域声明与平台规则引用。

### 商业模式

| 形态 | 优点 | 缺点 | 判断 |
|---|---|---|---|
| 开源 + 自备 Key | 无服务器成本、隐私好、传播快 | 无收入、API Key 门槛劝退非技术用户 | **保留为默认** |
| 托管 SaaS | 有收入 | 国内模型 API 需要备案；内容审核责任落到你身上；毛利被 API 吃掉 | 可做，但**先把 A 方案的付费意愿验证出来** |
| 桌面端（PyInstaller/Electron/Tauri） | 装起来就能用，避开 13 家 SDK 的依赖地狱 | 打包体积大、签名与更新麻烦 | **强烈建议**——当前 `pip install` 要装 13 家 SDK，对非技术用户是灾难 |
| 小程序 | 传播强 | 算力与内容审核受限，本地模型不可能 | 不建议 |

**关键结论**：当前"pip install -r requirements.txt（一次装 anthropic + openai + google-generativeai + 13 家支持）+ 手工填 API Key + 手工起 Web 服务"这条路径，把 90% 的潜在用户挡在门外。**桌面端一键包是提升实际用户数性价比最高的单项改造。**

### 开源运营

选墨集仓库状态：**无 `.github/` 目录 → 无 CI、无 Issue 模板、无 PR 模板**；`img.png` 存在但 README 未引用；截图外链到 `github.com/user-attachments/`（依赖上传者账号存续）；`README.md:274` 的 `[Issues](../../issues)` 相对链接指向错误仓库；TERMS 说 MIT 而 LICENSE 是 Apache-2.0。这些每一条都在**直接降低陌生访客的信任度和转化率**。

**这些是最高 ROI 的 2 小时改造。**
