# 选墨集 / Sifted-Ink — 缺陷与稳定性登记册

> 汇总 5 组专项评审（架构 / 产品 / 工程 / AI 效果 / 文档一致性）的缺陷发现，按严重度排序。
> **所有标 ✅ 的条目已由主会话逐条读源码复核确认**；其余为专项评审的静态分析结论，标注了推断依据。
> 全程未执行、未导入、未运行项目代码（本地权限策略限制），因此没有运行时实测数据。

## 严重度定义

| 级别 | 含义 |
|---|---|
| **P0** | 崩溃、数据丢失、密钥泄露、或"宣传的核心能力实际不存在" |
| **P1** | 功能结果错误（生成内容错、导出错、路由 400、跨版本串数据） |
| **P2** | 体验差（信息缺失、等待无反馈、重复烧钱、显示错误） |
| **P3** | 代码质量（死代码、命名不一致、魔法数字、文档漂移） |

## 五、根因聚类

| 根因 | 涉及缺陷 | 说明 |
|---|---|---|
| **R1 静默失效（不报错、不告警，只让结果慢慢变差）** | B-05 B-07 B-13 B-14 B-15 B-16 B-19 B-20 B-22 B-25 B-57 | **最危险的一类**。用户不会看到"出错了"，只会看到"生成质量差"，却无从定位。这是"bug 不少"这个感受的主要来源。 |
| **R2 账算不清** | B-18 B-21 B-33 B-43 B-19 | token 少算 3.7 倍 + 版本数无上限 + 每次刷新重生成前附文 + 导出重复调 LLM → 用户对花费毫无掌控感，也导致熔断机制形同虚设。 |
| **R3 承诺与实现脱节** | B-05 B-07 B-08 B-11 B-12 B-10 B-49~B-59 | README 描述的是"理想中的产品"，代码是"当时的实现"。两套并存，信任被消耗殆尽。 |
| **R4 无工程基座** | B-63 B-64 B-66 B-67 B-61 | 0 测试 / 0 CI / 0 锁文件 / 0 打包元数据 / 12 处吞异常 → 任何一次修改都是赌博。 |
| **R5 安全姿态与部署姿态不匹配** | B-01 B-02 B-03 B-04 | 本地工具的假设（"只有我能访问"）在 `0.0.0.0` + 无鉴权 + 收集 API Key 的前提下不成立。 |
| **R6 成本/质量权衡倒挂** | B-23 B-24 B-26 B-08 B-21 | 靠"多开版本、多花 token"换质量，而真正影响质量的东西（对话连贯、禁用词、风格规格、评估可信度）**一个都没做**。 |
